## 二、更新同步机制

App 采用**原生 WebView 外壳**，启动时直接加载线上地址：

```
https://sifreelee.github.io/self_introduction/
```

因此：

- 网站内容一旦 `push` 到 GitHub Pages，App 下次打开即是最新版，**无需重新打包、无需用户更新 App、用户不需要做任何操作**。
- App 本身只包含外壳与图标，不含网页快照，所以体积小、永不"过期"。

### 为什么能做到「网站更新 → App 自动最新」

关键是**主文档（HTML）永远走网络**，只有图片、样式这些子资源才用本地缓存：

| 请求类型 | 走哪里 | 原因 |
|---|---|---|
| 主文档 HTML | 每次打开都走网络 | 站点改版立刻生效，不依赖任何后台同步 |
| 图片 / CSS / JS | 本地缓存优先 | 打开快、省流量 |

这样设计的好处是：就算后台同步一次都没跑过、就算距上次同步还不到 6 小时，只要你能联网，打开 App 看到的永远是线上最新的 HTML。

弱网或断网时主文档拉不到，`onReceivedError` 会把本地缓存的那份 HTML 顶上来（`loadDataWithBaseURL`，base 设成线上地址），页面里的图片样式仍由拦截层从缓存提供，所以断网也能完整浏览上次的内容。

开启离线缓存后，子资源走**缓存优先**：直接由本地文件渲染，几乎瞬间打开；后台再用条件请求（`If-None-Match` / `If-Modified-Since`）核对差异。发现 HTML 有实质变化时自动刷新一次页面。

## 三、离线缓存

### 首次启动

会弹窗询问，三选一：

| 选项 | 含义 |
|---|---|
| 全部缓存 | 页面 + 文字 + 全部照片（约 200 MB 以上），设置里显示实时进度 |
| 仅打开时缓存 | 只保留你实际看过的页面与该页照片，随看随存，不占额外空间 |
| 不缓存 | 完全走网络，每次重新加载 |

默认勾选「仅 Wi-Fi 下缓存」。若当前不是 Wi-Fi，同步会被跳过并提示，等接入 Wi-Fi 后自动生效。

这个弹窗**只在第一次打开时出现一次**。选错了或当时没成功，随时可以在「设置」里改。

### 设置面板

**入口**：导航栏上、三条杠左侧的「设置」按钮，位置是「洛晴跃飞 …… 设置 ☰」。
按钮由 App 在页面加载后注入 `#nav-toggle` 之前，用 `margin-left:auto` 贴住三条杠；它不在下拉菜单里，一眼就能点到。
如果哪天站点改版导致注入失败，**长按页面空白处**也能打开同一个面板。

面板内容：

| 区块 | 内容 |
|---|---|
| 缓存方式 | 全部缓存 / 仅打开时缓存 / 不缓存，三选一；切换「全部缓存」会立即开始同步 |
| 缓存进度 | 仅「全部缓存」下显示：`正在核对 128 / 695 项 · 86 MB`，下方进度条，可点「立即同步」 |
| 仅 Wi-Fi | 勾选后仅在 Wi-Fi 下下载内容 |
| 显示密度 | 「每行相册」滑杆 0–4：数值越大每行相册越多、单张越小；0 为跟随站点默认 |
| 缓存占用 | 当前已缓存体积与项数，附「清除已缓存内容」按钮 |

显示密度保存在 `SharedPreferences`（`app_pref` / `photo_columns`），重启 App 仍生效。它同时作用于相册列表网格与相册内大图网格，浏览时观感一致。

### 之后如何更新

- **打开 App**：主文档直接取线上最新；距上次同步超过 6 小时的话，后台再核对一次子资源
- **下拉刷新**：强制重新加载并触发一次后台核对（忽略 6 小时节流）
- **设置 → 立即同步**：忽略「已缓存不重复下载」的规则，把本地已有的也跟服务器逐一核对（走 304，基本不耗流量）
- **设置**：查看进度、切换缓存方式、清除缓存

### 只补缺口，不重新缓存

同步不是"每次都把 695 项重下一遍"，而是按缺口来：

| 情况 | 处理 |
|---|---|
| 本地没有 | 下载（切到「全部缓存」后的第一遍就是这种） |
| 本地有、7 天内核对过 | **直接跳过，一个请求都不发** |
| 本地有、超过 7 天 | 发一次条件请求，服务器回 304 就不下载，只更新核对时间 |
| 页面 / CSS / JS | 每次都核对（数量少、体积小），保证改版立刻发现 |
| 点「立即同步」 | 忽略 7 天规则，全部核对一遍 |

所以第二次、第三次同步几乎不产生流量：进度条上的总数是**真正需要核对的项**，不是 695。

（图片 URL 若带 `?v=` 这类查询串也能正确识别为图片，不会被误当成页面资源反复核对。）

### 实现要点

- 缓存落在应用私有目录 `files/webcache`，索引是同目录下的 `index.json`，卸载 App 即彻底清除
- 拦截层 `shouldInterceptRequest` 只处理本站 GET 请求，缓存命中直接返回本地文件，未命中放行网络
- 服务端返回 304 视为未变；若服务端不返回 304，再用 SHA-1 内容哈希兜底，避免"每次都判成更新"
- 单文件上限 24 MB，超限跳过，防止异常文件撑爆存储
- 自动刷新每次会话最多触发一次，避免个别资源反复判为变更导致页面来回 reload
- 「仅打开时缓存」复用同一套流程，只是把待存清单限定为当前页枚举到的资源；该模式不受 6 小时节流限制，且不弹提示

## 四、图片与文字

### 保存图片

在页面里**长按任意图片**（包括点开大图后的大图本身），弹出菜单：

| 操作 | 说明 |
|---|---|
| 保存图片到相册 | 存入 `Pictures/洛晴跃飞/`，相册与文件管理器可见 |
| 复制图片链接 | 便于分享原图地址 |

保存时**优先取已缓存的文件**，没有缓存才走网络，因此离线状态下也能保存看过的照片。

Android 10 及以上使用分区存储，无需任何权限；Android 7~9 会请求一次存储权限。

### 复制文字

页面文字**保留系统原生的长按选择能力**：长按正文 → 出现选择光标与「复制 / 全选」菜单。

这里刻意做了取舍：App 只用注入脚本接管**图片**的长按，正文、标题、`<a>`、按钮一律放行，
所以选字、扩选、复制都与浏览器一致。相应地，代码中绝不能调用 `setLongClickable(false)`，
那会连带废掉文本选择。

## 五、手机安装方法

1. 把 APK 通过微信 / QQ / 数据线传到手机。
2. 点击 APK，系统提示"未知来源应用"，按引导允许**文件管理器**或**微信**安装未知应用。
3. 安装完成后，桌面出现朱红印章图标，名称为「洛晴跃飞」。
4. 若曾安装过旧版本，直接覆盖安装即可（签名一致）。

> 微信内置打开 APK 可能被限制，建议用"用其他应用打开"或直接到文件管理器点击。

## 六、换图标（一键）

把图片**拖到 `set-icon.bat` 上**即可，或者双击它、在弹出的对话框里选图。

脚本会自动完成整条链路：

```
set-icon.bat
  └─ set_icon.py
       ├─ 1/4 归一化图片（任意格式统一存为 custom-icon.png）
       ├─ 2/4 生成图标资源（5 档密度 + 自适应图标 + 圆形图标）
       ├─ 3/4 Gradle 打包
       └─ 4/4 输出到 dist/，并自动打开该文件夹
```

全程约 20～100 秒（首次编译较慢，改过图标后 Gradle 需要重跑资源合并）。成品直接拖进微信就能发给别人。

支持 PNG / JPG / WEBP / BMP，任意尺寸。脚本会自动判断图片来源类型：透明底 logo 裁掉留白后居中；白底墨迹图抠出主体并把白纸底转透明；照片则铺满整块图标。

底色与占比在 `make_icons.py` 顶部调整：`CUSTOM_BG`（当前纯黑）、`SAFE_RATIO`（当前 0.76）。

### 导航栏自动收起

站点本身的 `.navbar` 是 `position: fixed`，滚动时 JS 只切换 `.scrolled` 的磨砂底色，**从不隐藏**（`css/style.css:84`、`js/main.js:1041`）。所以在手机上会一直占着 68px。

App 在这种情况下通过 `onPageFinished` 注入一段脚本（`MainActivity.NAV_AUTOHIDE_JS`），只作用于 App 内部，**不改网站源码**：

- 向下滚动超过顶栏高度 1.2 倍 → 顶栏 `translateY(-105%)` 收起
- 向上滚动 → 立即唤出
- 页面顶部附近、汉堡菜单展开时、点击导航锚点后 0.9 秒内 → 不收起
- 位移阈值 8px，避免手指轻微抖动误触发

如果希望网站本身也具备这个行为（浏览器访问同样生效），把同样的判断写进 `js/main.js` 与 `css/style.css` 即可，但要注意别和 `.scrolled` 的过渡冲突。

## 十一、已知限制

- 未做推送通知；网站更新不会主动提醒，需打开 App 或下拉刷新才会同步。
- 缓存只覆盖 `SITE_DATA` 中登记、且页面实际引用过的资源；临时新增但未在页面出现的文件不会被缓存。
- 站外链接会交给系统浏览器打开，App 内不承载第三方页面。
- 未在真机上做逐机型验证，仅完成构建产物校验（包名、签名 v2、资源、启动 Activity 均正常）。
- 「设置」按钮是动态插进导航栏的。若日后站点改掉 `.nav-inner` / `#nav-toggle` 结构，按钮位置可能变化或失效，此时长按页面空白处仍可打开面板。
