## 相册面板左上角印章自动缩字号（同日追加）
- 问题：`.album-browser-seal` 固定 30×30、字号写死 15px，`圆明园`(3字)、`构件`/`坛庙`/`伪满`(2字) 等印章文字会飞出红块。
- CSS：加 `box-sizing:border-box; padding:3px; line-height:1.1; flex-wrap:wrap; align-content:center; text-align:center; overflow:hidden`。
- JS：新增 `fitSealText(el)`，`openAlbum()` 里设完 `seal.textContent` 后调用。算法：可用区 maxW/maxH = clientW/H − 6；先算两种摆法的字号——单行 `maxW/n`、两行 `min(maxW/ceil(n/2), maxH/(2*1.1))`，取更大的那个（封顶 15px）；再从该字号往下 0.5px 一档实测 `scrollWidth/scrollHeight` 收一次，兜住楷体字宽不是整 1em 的情况。
- 结果：1 字 15px、2 字 12px 单行、3 字及以上折两行约 11px，均不出框。
- 另：封面卡片的悬浮印章 `.photo-seal` 是另一套逻辑（`sealHTML()` 按字数缩字号并改成长条），不要混用。
- 版本号 → `?v=20260923d`。
- 印章字号改为**按字数分档递减**（用户要求「1字大、2字小、3字更小」）：`fitSealText()` 用 `{1:19, 2:12.5, 3:8.8}` 查表，再与 `maxW/n`、`maxH/1.1` 取小；≥4 字才折两行。CSS padding 3px→2px（可用区 26×26）。实测兜底循环保留。版本号 → `?v=20260923e`。

### 坑：用户在 data.js 里改 desc 却不生效
- 原因：`noteSource()` 优先级是 `js/album-desc.js` > `data.js desc`；那两本（镇馆之宝 / 中国 北京）在 album-desc.js 里有我填的示例文字，把 data.js 的 desc 盖住了。
- 处理：把用户写的「自行拍摄整理的国内镇馆之宝」「自行拍摄整理各个北京景点」搬进 album-desc.js，data.js 对应 desc 清空。
- 结论：**同一本相册两边都写时以 album-desc.js 为准**，以后回复用户要第一时间提醒他改哪个文件。

### 关键坑：flex 居中容器量不出溢出（印章字号被压到 7px）
- 现象：加了自动缩字号后所有印章变成 7px（比原来还小），用户反馈「没改」。
- 根因：`fitSealText()` 用 `el.scrollWidth/scrollHeight` 判断溢出，但 `.album-browser-seal` 是 `display:flex` 居中容器——内容居中溢出时 **scrollWidth 恒等于 clientWidth（30）**，永远「检测到溢出」，缩小循环一路走到 MIN=7px。
- 修法：把文字包一层 `<span class="seal-text">`，量这一层的 `getBoundingClientRect()` 宽高（溢出也能量到真值），再和可用区（clientW/H − 2*PAD）比。
- 实测（Edge headless `--headless=new --dump-dom` + 页面末尾注入脚本调 `openAlbum(i)` 输出结果）：1字 19px（文字 18.7×20.6）、2字 12.5px（24.6×13.5）、3字 8.7px（25.6×9.4），可用区 26×26，全部在框内。
- 这个「复制 index.html → 注入测试脚本 → 无头 Edge dump-dom」的验证套路很好用：main.js 是顶层脚本、函数声明会提升，所以即使页面初始化报错也能直接调 `openAlbum()` 测。测完记得删临时页。
- 版本号 → `?v=20260923f`。

## compress.py 透明 png 底色（下午）
- 用户要求「抠图 png 转 jpg 时背景别用纯白、要和网站配色相近」——**该功能早已内置**：`save_jpg()` 里 `has_alpha` 判断（RGBA / LA / P+transparency）后把透明区合到 `BG_COLOR`；`read_css_color()` 从 `css/style.css` 读 `--card`（#F6F0E2，正好是 `.photo-card` 的底色）。
- 实测（Temp 目录造 RGBA / P+tRNS / LA 三种透明 png 跑一遍再读角落像素）：三种都得到 (246,240,226)，不是白色。
- 新增：`--bg` 命令行参数（`#RRGGBB` 或 css 变量名），`parse_bg()` 解析；`ARGS` 全局存 argparse 结果；实测 `--bg "#EFE8D6"` → (239,232,214) 生效。
- 重要限制（已写进脚本文档和使用说明）：只对**真透明**生效；白底不透明的抠图 png 不会去白底，否则会误伤正常白色高光，需用户先在抠图软件里存成透明通道。
- 环境坑：Bash 工具的 shim 在这台机器上 `dirname/cd/mkdir` 常报 command not found，多步命令链容易断；用 PowerShell 工具更稳，`python -c` 带换行的脚本也尽量写成 .py 文件再跑。

## rename_album.py 新增「重命名模式」四选一（傍晚）
- 需求：把原来的布尔开关 `--allow-chinese` 升级成四种模式——只重命名英文 / 只重命名中文 / 都不重命名 / 都重命名。
- 实现：`RENAME_MODES` 表（`en`/`cn`/`none`/`all`，含中文名与说明）+ `MODE_KEYS` + `mode_label()`，问答模式与命令行共用这张表，改一处两边同步。
- `select_files()` 参数 `allow_chinese=False` → `name_mode="en"`；第 2 步按模式分流：`none` 全部进 keeps、`cn` 只留 has_cjk 的、`all` 全改、`en` 排除 has_cjk。第 3 步「已编号跳过」规则不变（none 模式下 plan 为空自然跳过）。
- 返回值第 4 项 `skipped_cjk` → `skipped_by_mode`（通用措辞，cn 模式下指的是英文名文件）。
- CLI：`--rename-mode {en,cn,none,all}` 默认 en；旧 `--allow-chinese` 保留，在 main() 里映射成 `all` 兼容。
- `print_plan()` 增加 plan 为空的分支（none 模式下输出「本次不修改任何文件名」+ 全量 keeps 列表），否则会显示「将要这样改（共 0 张）」很怪。
- 顺手修 bug：`write_outputs()` 里 `os.path.relpath(img_dir, DEFAULT_IMG_DIR)` 在照片文件夹与站点**不在同一盘符**时抛 `ValueError: path is on mount 'C:', start on 'F:'`——此时文件已改完名却拿不到清单。已用 try/except 兜住，跨盘时按 `assets/images` 根处理。
- 实测（Temp 目录造 3 英文 + 3 中文名）：四种模式 dry-run 结果正确；`cn` 模式真实执行后中文名→t1/t2/t3、英文名原样，对照表「原名保留」行正常；问答模式管道输入选 2 也能正确走 cn。
- `使用说明.md`「零点二」第 6 步改为四选一表格，并注明旧参数等价关系。
