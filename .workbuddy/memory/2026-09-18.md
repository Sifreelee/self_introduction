## 图集缩略图选择器（相册点开先看全部小图）
- 需求：点击任意相册 → 长条悬浮框，一行三张缩略图，可下滑、渐入动画；点某张再进灯箱（保留上一张/下一张）。
- 实现：`index.html` 新增 `#album-browser`（backdrop + sheet + head + body）；`js/main.js` 新增 `openAlbum()` 渲染缩略图、`openLightbox(i)` 从指定索引进灯箱、Esc 先关灯箱回到选择器；`css/style.css` 新增 `.album-browser-*` 与 `@keyframes thumbIn`。
- 用户后续两条微调：
  1. 小图必须显示完整 → `.thumb-cell img` 从 `object-fit: cover` 改为 `contain`（留白垫 `--paper-3`），hover 缩放 1.06→1.04。
  2. 右侧极细下滑进度条 → 网格外层包 `.album-browser-body`（`position:relative; flex:1; min-height:0`），里面放 `.album-browser-rail`（2px 轨道）+ `.album-browser-rail-thumb`（3px 朱砂滑块）。原生滚动条隐藏（`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`）。
- 关键坑：进度条不能放在滚动容器内部（会跟着内容滚），必须挂在外层 wrapper 上；`flex` 子项要显式 `min-height:0` 才能正确滚动。高度随图片加载变化，需 rAF + 图片 load 事件 + 400ms 后各刷一次。
- 资源版本号习惯：改完前端文件把 `index.html` 里 `?v=YYYYMMDDx` 递增一位，避免浏览器缓存。

## 下午的返工（重要教训）
- **灯箱打不开的真凶**：`openAlbum()` 改成开选择器后只给 `browserPhotos` 赋值，`albumPhotos` 一直是空数组，而 `openLightbox()` 开头 `if (!albumPhotos.length) return;` → 点缩略图毫无反应。改成点击缩略图时同步 `albumPhotos = browserPhotos; albumCity = browserGroup.city`。
- **统一缩略图方框做不得**：`.thumb-shot` 固定 4:3 + `object-fit: contain` 的方案被否，用户要求「直接放照片」——`img` 改 `width:100%; height:auto`（原始比例、不裁不压），去掉边框/底色，只留 8px 圆角 + 轻投影。
- **补空位**：网格 `grid-auto-rows: 8px` + `ResizeObserver` 按单元格实际高度算 `grid-row-end: span N`（`N = ceil((h+14)/(8+14))`），做瀑布流；同时去掉 `loading="lazy"` 避免加载后跳动。
- **灯箱外壳来回改了两轮，最终回到原样**：先做成 0.8 透明纸框 + 14px 圆角 + backdrop-blur（用户嫌不好看）→ 恢复成原来的「深色背景 + 6px 米色边框 + 下方题字」，只在 `img` 上加 `border-radius: 6px`。教训：这个站点的放大展示样式用户已认可，不要擅自重做外壳；改动应限定在「加一点圆角」这种量级。
- 曾尝试用 JS 按照片比例计算外壳宽度（`fitLightboxShell`），已随回退一并删除。

## 加新照片的流程（用户问的）
- 只把文件丢进 `assets/images` 不会显示，必须写进 `js/data.js` 的 `photos` 数组。
- 进了 data.js 之后，展示（一行三张、瀑布流、灯箱、上一张/下一张、圆角）全自动，张数不限。
- 两条快捷路：① `add-tool.html`（浏览器打开，填城市名+照片清单，可生成片段或直接导入 data.js 下载覆盖）；② `rename_album.py` 批量改名时顺带生成 `<前缀>_datajs片段.txt`。
- `compress.py` 只同步 data.js 里的旧文件名（png→jpg），不会新增条目。

- 新增：`选择图片文件夹…` 按钮（`<input webkitdirectory directory multiple hidden>`）+ 虚线拖拽区（用 `webkitGetAsEntry()` 递归读目录）。
- 三个勾选：追加到现有清单（默认开）/ 包含子文件夹（默认关，只取当前层）/ 用文件名当标题（默认关）。

## 灯箱照片边缘渐隐（三轮定稿）
- 用户诉求演变：边缘玻璃质感 → 向外模糊渐隐（做过 halo 模糊副本层）→ **只要渐隐、不要光晕**（定稿）。
- 定稿实现：`#lightbox-img` 上用 4 条线性渐变 mask + `mask-composite: intersect`，四边各 `--edge: 22px`（变量在 `.lightbox-shot` 上，改一个数即可）；投影保留在外层 `.lightbox-shot` 上（mask 会把 box-shadow 一起裁掉，所以不能放 img 上）。
- **重大坑（导致「图片不见了」）**：主图样式曾写成 `.lightbox-figure img`（0,1,1），优先级高于 `.shot-halo`（0,1,0），把 halo 的 `position:absolute` 覆盖成 `relative`，halo 变占位块把真照片挤出视口。教训：灯箱内新增图层时，主图规则必须用 `#lightbox-img`（id 级）收窄，别用后代 img 泛选。
- `.lightbox-shot` 的尺寸由 ResizeObserver 按照片实际渲染尺寸同步（照片被 max-height 压窄后外层 span 不会自动跟着缩）。
- 验证方式：agent-browser 真实浏览器 `open → find first .photo-album click → find first .thumb-cell click → get box → screenshot`，可直接看到 mask 渐隐效果；注意改完文件必须重新 `open`（旧页面 DOM 不会自动刷新）。
- **圆角被渐隐吃掉的坑**：圆角半径必须明显大于 `--edge`，否则圆角整圈落在渐隐带里、边缘一淡就看不出圆角（16px 圆角 + 22px 渐隐 = 看不出）。现为 `--edge: 16px` / `--radius: 30px`，两个变量都写在 `.lightbox-shot` 上，改一处即可。浏览器 `open → find first .photo-album click → find first .thumb-cell click → get box → screenshot`，可直接看到 mask 渐隐效果；注意改完文件必须重新 `open`（旧页面 DOM 不会自动刷新）。
- 灯箱最终形态（用户逐轮拍板后的定稿）：深色背景 + 无白边 + `border-radius: 16px` + 原阴影 `0 30px 80px rgba(0,0,0,.55)` + 下方米色题字。演进顺序：原样（6px 白边）→ 透明纸框（被否）→ 恢复原样 + 6px 圆角 → 去白边 + 16px 圆角。
- 校验内联脚本的办法：正则抽出 `<script>` 内容另存 .js → `node --check`；再用正则比对 `$("id")` 与 HTML 里的 `id=` 是否对得上。
- **路径写死的 bug（用户反馈）**：`buildSnippet` 里 `src` 前缀硬编码 `assets/images/`，照片放子目录就链接错。修法：新增 `图片所在文件夹` 输入框（id `p-base`，默认 `assets/images`）作为前缀；选文件夹后若该框仍是默认值，自动改成 `assets/images/<文件夹名>` 并在提示里说明可手改；`toItems()` 把 `webkitRelativePath` 转成相对所选文件夹的 path（含子目录），拖拽目录则在递归时拼 prefix 保留结构。
- 验证技巧：jsdom 装不上（npm 在托管 workspace 里装不动），改用 `new Function("window","document","navigator", 抽出的脚本 + "return {...}")` 暴露内部函数，配极简 DOM 桩（getElementById 返回带 value/textContent 的假元素）直接在 Node 里跑真实逻辑，10 项断言全过。
