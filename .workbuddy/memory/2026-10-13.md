# 2026-10-13

## tools.bat 报 ModuleNotFoundError: No module named 'PIL'（已修复）

根因：compress.bat / rename_album.bat / tools.bat 里写死的解释器是 WorkBuddy 托管的
`...\binaries\python\versions\3.13.12\python.exe`，它是干净隔离环境，没有 Pillow。
（Anaconda 里倒是有，但 7.2.0 太老。）

修复过程（两个坑都记下）：
1. `binaries\python\envs\default` 原是个**坏 venv**——目录在但没有 python.exe。
   删掉重建后，venv 的解释器**不在根目录而在 `Scripts\python.exe`**（这台机器的布局如此），
   bat 里要写全 `envs\default\Scripts\python.exe`。
2. 在 Git Bash 里用 `python -c "..."` / heredoc 写含反斜杠的 Windows 路径，
   会被 MSYS 转成正斜杠（连 `r'...'`、heredoc 引号都拦不住）。**解法：把逻辑写进临时 .py
   文件再运行**，或用 `chr(92)` 拼路径。跑完记得删临时文件。

结果：
- 重建 `envs/default` venv，`pip install pillow`（12.3.0）
- 三个 bat 的解释器路径统一替换为
  `C:\Users\lenovo\.workbuddy\binaries\python\envs\default\Scripts\python.exe`
  （4 处：compress.bat×2、rename_album.bat×1、tools.bat×1），保持纯 ASCII + CRLF

验证：临时文件夹实测——PIL 导入通过；3000×2200 大图 0.34MB → 0.03MB（缩到 1600px 内）；
合格 jpg 正确跳过；tools.bat 菜单 0 退出路由正常。测试目录已删。

**以后凡是新 bat / 新脚本要用第三方库，解释器一律用
`C:\Users\lenovo\.workbuddy\binaries\python\envs\default\Scripts\python.exe`；
缺库就 `...\Scripts\python.exe -m pip install <库>`，别再指到 versions\3.13.12 裸解释器。**
