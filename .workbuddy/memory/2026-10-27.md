## 将个人网站打包为安卓 APK

用户需求：把 https://sifreelee.github.io/self_introduction/ 打成 APK 分享给安卓手机，且**网站更新能自动同步**。

### 方案决策
采用**原生 WebView 外壳**（不内置静态快照）：
- 启动直接加载线上地址，网站 push 后 App 下次打开即最新，无需重新发版。
- 对比离线包方案：离线包要把 assets 下 700+ 张照片全打进去，体积大且每次改版都要重发 APK；WebView 壳仅 435 KB，一劳永逸。代价是必须联网。

### 构建环境搭建（本机一次性）
- Android SDK：`F:\android-sdk`（platform-tools + platforms;android-34 + build-tools;34.0.0），cmdline-tools 装在 `cmdline-tools/latest`
- Gradle 8.9：`F:\android-build\gradle-8.9`（腾讯镜像下载）
- AGP 8.7.3 + JDK 17

**网络坑（重要）**：
- `dl.google.com` 直连可用；`maven.google.com` 经代理返回 **502**，必须走 `https://maven.aliyun.com/repository/google`。已在 `settings.gradle` 固化镜像。
- `services.gradle.org` 不可用 → 生成 wrapper 会因 URL 校验失败报错，需 `--gradle-distribution-url` 指向腾讯镜像并加 `--no-validate-url`。
- curl 访问 https 需加 `--ssl-no-revoke`（schannel 证书吊销检查失败）。
- `maven.aliyun.com/repository/gradle-plugin` 返回 404，但 AGP 走 google 镜像即可。

- 包名 `com.sifreelee.intro`，minSdk 24 / targetSdk 34，versionName 1.0.0
- 图标：`make_icons.py` 用 Pillow 生成朱红印章「清」字（华文行楷风格以外的 msyhbd），含 5 档密度 PNG + adaptive icon XML

## v1.0.1 修复：页面只能单向下滑

**症状**：App 内网页只能往下滚，无法往回滚到上方。

**根因**：`SwipeRefreshLayout` 的直接子 View 被包了一层 `FrameLayout`。
`SwipeRefreshLayout.canChildScrollUp()` 默认调 `child.canScrollVertically(-1)`，
而 `FrameLayout` 恒返回 false，于是外壳永远认为"已在顶部"，
每次手指下拉（想回滚）都被下拉刷新消费掉。

**修复**：
- WebView 改为 `SwipeRefreshLayout` 的直接子 View，进度条移到外层 FrameLayout
- 增加内部类 `WebSwipeRefreshLayout`，重写 `canChildScrollUp()` 直接查 WebView 滚动位置（双保险）
- 下拉刷新去掉 `clearCache(false)`（会清掉整站照片缓存，刷新后长期白屏），改为只 `reload()`

用户要求"随意上传图标"，做成拖拽式一键脚本：

**已实测**：用绿色测试图跑完整链路，解包 APK 确认 192px 图标四角变为 (0,128,0,255)，
再换回 logo 后恢复为 (0,0,0,255)，签名校验通过。说明资源变更能被 Gradle 正确捕获。

## v1.0.3 导航栏下滑收起

用户反馈"表头三条杠那块下滑不上缩，一直卡在那里"。

**排查结论：不是 App 的 bug。** 站点 `.navbar` 是 `position: fixed`（`css/style.css:84`），
`js/main.js:1041` 只做 `navbar.classList.toggle("scrolled", scrollY > 40)`，
而 `.scrolled` 仅加磨砂底色（`style.css:89`），从未隐藏或缩小导航栏。浏览器里同样常驻 68px。

**处理方式（App 侧注入，不动网站源码）**：
- `MainActivity.NAV_AUTOHIDE_JS` 常量 + `onPageFinished` 时 `evaluateJavascript` 注入
- 向下超过 navH*1.2 加 `.nav-autohide{transform:translateY(-105%)}`，向上立即移除
- 抑制条件：位移 <8px、页面顶部、汉堡菜单展开、点击导航锚点后 900ms
- 开关 `ENABLE_NAV_AUTOHIDE`，置 false 即恢复站点原样
- 注意：`transform` 会让 `position:fixed` 的后代（移动端 `.nav-links`）改变包含块，
  所以菜单展开时必须禁止收起，否则菜单会被一起推走

**验证手段**：解包 dex 确认脚本字符串已编入；另用 Node + 最小 DOM 桩跑 9 组滚动序列，
收起/唤出/阈值/菜单保护全部符合预期。

## v1.1.0 离线缓存 + 图片保存 + 文字复制

用户新增三条需求：弱网先出缓存、首次询问是否缓存且之后增量、点开图片可下载、文字可复制保存。

### 关键数据
站点 `assets/images` 共 **695 张 jpg / 196MB**，平均 285KB。全量缓存必须让用户知情，
因此做成首次启动三选一（缓存全部 / 仅页面文字 / 暂不缓存），默认勾选仅 Wi-Fi。

### 新增文件
- `WebCache.java`：缓存存储 + 增量同步
  - 私有目录 `files/webcache`，索引 `index.json`（url / fileName / etag / lastModified / hash / size）
  - 条目文件名 = SHA-1(url) + 扩展名
  - 同步走 `HttpURLConnection` + `If-None-Match` / `If-Modified-Since`，4 线程并发
  - **关键兜底**：GitHub Pages 若不返回 304，用 SHA-1 内容哈希比对，避免每次判成更新
- `MediaSaver.java`：图片入相册。API 29+ 走 MediaStore 分区存储（无需权限），
  API 24-28 写公共 Pictures + MediaScanner，需 `WRITE_EXTERNAL_STORAGE`（manifest 限 maxSdkVersion=28）

### MainActivity 改动要点
- `shouldInterceptRequest`：只处理本站 https GET，命中缓存直接返回 `WebResourceResponse`，
  文本类给 UTF-8 编码；异常一律返回 null 退化为网络，不能白屏
- 下拉刷新时 `bypassCacheOnce` 放行一次主文档，否则缓存优先下永远拿不到新 HTML
- 普通打开节流 6 小时；菜单/下拉刷新置 `pendingForceSync` 强制同步
- 自动刷新每次会话最多一次（`autoReloaded`），防止个别资源反复判更新导致 reload 死循环
- JS 桥 `AndroidBridge`：`onImage` / `onBlank` / `onAssets`，全部 `ui.post` 切主线程
- 长按用注入 JS 实现（touchstart + 520ms 定时器 + 10px 位移取消），**不用**
  `setOnLongClickListener`/`setLongClickable(false)`——那会废掉 WebView 原生选字

### 资源枚举
`COLLECT_JS` 递归遍历 `SITE_DATA`（不硬编码结构）+ DOM 查询 css/js/icon，
统一转绝对 URL。实测 8 项样本：中文文件名正确 URL 编码、`?v=` 查询串保留、
纯文本字段未误收、首页被包含。

### 验证
- 三段注入 JS 用 node --check 全部通过
- COLLECT_JS / INTERACT_JS 用 DOM 桩跑通：图片长按回调、正文长按放行、链接放行、
  空白回调、按下后滑动不误触发
- 解包 dex 确认 AndroidBridge / WebCache / MediaSaver / index.json 均已编入
- 未做真机验证（无设备），缓存命中与相册写入仅在代码层面核对

## v1.1.5 设置入口提前注入 + 缓存四处修复

### 需求
1. 「设置按钮一打开界面就得在标题栏上」
2. 「现在那个缓存还是有 bug，检查一下」
3. 澄清：之前那句「不要点就直接出来」指的是**按钮**要在，不是面板自动弹 → 已回滚启动自动弹面板

### 设置入口提前注入
- 原来只在 `onPageFinished` 注入。首页几十张相册封面，onPageFinished 要等好几秒，
  这几秒里标题栏是空的
- 改用 `WebViewClient.onPageCommitVisible`（注意：`onProgressChanged` 是
  **WebChromeClient** 的回调，写在 WebViewClient 里 @Override 会编译不过）
- `SETTINGS_BTN_JS` 改成 `ensure()` + 重试：100ms×120 次、`DOMContentLoaded`、
  `window.load`、外加 400ms×38 次的兜底轮询（找到即 clearInterval）
- `btnInjected` 按导航生命周期复位（`onPageStarted` 置 false）

### 缓存审查出的 4 个真 bug
1. **「仅打开」被当成全量下载**：`COLLECT_JS` 会 `walk(SITE_DATA)` 把 data.js 里
   695 张照片全捞出来，于是「只存看过的」= 一开就狂下全部。新增 `COLLECT_DOM_JS`
   （只认 `img[src]` 等真实 DOM），`collectAndSync()` 按模式选脚本
2. **并发同步**：`sync()` 无互斥。换页 / 刷新 / 手动同步会叠加跑两轮 →
   `pTotal` 被覆盖、先结束的把 `syncing` 置否（面板显示已完成实际还在下）、
   `saveIndex()` 并发写。改成 `syncLock` + `syncRunning` + 队列，
   跑完自动补跑一轮（`startBatch` 拆出来）
3. **索引只在整轮结束落盘**：首轮几百张要跑几分钟，中途退出/被杀 → 文件在、
   索引没写 → 下次全部重下。改成每 25 项 `saveIndex()` 一次
4. **空任务空转**：`targets` 为空时仍 `syncing=true`，面板永远显示「正在检查更新…」。
   改成直接回调「本地已是最新，无需重新缓存」
- 附带：超大文件（>48MB）记住并跳过，避免每轮白下一半；`clear()` 顺手清队列和索引
