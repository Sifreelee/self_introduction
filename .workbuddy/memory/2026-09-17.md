## rename_album.py：中文名文件不改名，但必须进清单
- 需求：被保护规则挡下的文件（中文名 / 已编号）保持原名，但要写进照片清单、对照表、data.js 片段，方便整段复制。
- **关键改动：筛选顺序由「先套保护规则、再圈范围」改为「先圈范围、再套保护规则」**。原因是原来先过滤掉中文名文件，剩下的「跳过集」是相对整个文件夹计算的，会把别的图集的中文名文件（如 `编辑这张水墨山水画.jpg`）误带进来；改后只有落在本次批次范围内的文件才会被列为 keeps。
- `select_files()` 返回改为 4 元组 `(files, keeps, skipped_existing, skipped_cjk)`，keeps = [(文件名, 原因)]，按同一排序规则排好。
- **行为变化（需留意）**：`--newest N` 的 N 现在按全部图片计数（含中文名的），不再只数待改名的文件。同理 `--since` / `--match` / `--all` 的批次范围先算，再从中挑要改名的。
- 输出：清单追加在改名条目之后，格式一致（文件名 + 空格 + 标题，带扩展名）；CSV 中这些行的「编号」列写 `原名保留`，新文件名 = 原文件名；data.js 片段同样包含。
- 回滚：`rollback()` 增加 `新文件名 != 原文件名` 过滤，「原名保留」行自动跳过，不会做无谓的两次 rename。
- 新增 `--exclude-kept` 开关（默认关）：清单只列本次改名的部分。
- 测试 21 项断言全通过（`F:\WorkBuddy\_rename_test\test_keeps.py`，沙盒已清理）。教训：沙盒测试的每个场景前必须 reset 清空 IMG/OUT，否则上一轮残留会让后续场景莫名失败；PowerShell 回显 python traceback 时中文乱码，用 `*>&1 | Out-File` 抓即可。

## compress.py：支持选择压缩文件夹
- 需求：compress 小程序能选任意文件夹，不再写死 assets/images。
- 实现：`resolve_dir()` 用 argparse 取 `--dir`（空则交互式 `input()` 询问，直接回车用 `DEFAULT_IMG_DIR`），新增 `-r/--recursive`（os.walk 遍历子文件夹，报告里显示相对路径）。`IMG_DIR` 改为运行时赋值的全局量。
- **关键约束**：只有当目标文件夹 == 项目 `assets/images` 时才同步 data.js 与做引用检查（`sync_js` 开关），压其它地方的照片绝不改 data.js。
- 配套：`compress.bat` 支持把文件夹拖到 bat 上（`%~1` 传给 `--dir`），无参数则走交互式；仍保持纯 ASCII。
- 细节：递归模式下临时文件和目标 jpg 必须落在**文件所在目录**（`os.path.dirname(path)`），不能一律放 IMG_DIR 根。
- 测试 19 项断言全通过（`F:\WorkBuddy\_ctest\test_dir.py`，沙盒已清理）：外部文件夹不碰 data.js（md5 比对）、svg/gif 保留、子文件夹默认不处理而 -r 处理、交互式输入、不存在的目录报错退出。

- **踩坑：bat 里不能写中文**。第一版 `rollback.bat` 用 UTF-8 写了中文提示，cmd 按 GBK 解析，某些 UTF-8 字节对被解成 `|` `&` 等符号，把一行拆成多条命令，报「'樿创瀵圭収琛ㄧ殑瀹屾暣璺緞鍚庡洖杞?' 不是内部或外部命令」。已改为纯 ASCII 英文提示 + `chcp 65001` + `PYTHONUTF8=1`（ASCII 内容无解析风险，chcp 只用于让 python 的中文输出正常显示）。项目内 rename_album.bat / compress.bat / push.bat 复查均为 0 非 ASCII 字节，无此问题。
