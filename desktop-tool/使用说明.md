# 山水清音 · 桌面管家

双击 `ShanshuiManager.exe`。请保留同目录的 `_internal` 文件夹；移动程序时移动整个 `ShanshuiManager` 文件夹，放在 F 盘或其他非 C 盘。

## 查看处理进度

窗口顶部显示任务阶段、数量、百分比和已用时间。添加照片、压缩导出、改名、ZIP 打包和图片检查均显示真实进度，写入与代码更新完成后显示 100%。GitHub 的真实上传进度显示在弹出的 `push.bat` 窗口中。

## 换电脑或更换网站位置

顶部“选择网站文件夹…”可选择任意非 C 盘的网站位置，无需修改源码。选择包含 `index.html`、`js/data.js`、`css/style.css` 的整个文件夹，程序会验证结构并记住位置，所有模块同步、压缩路径、相册和 GitHub 操作均使用当前选中的网站。

程序会自动寻找自己所在目录、上级目录或旁边的 `personal-website`。程序与网站一起移动且相对位置保持不变时，可以自动找回；旧电脑路径失效且未能自动找到网站时，顶部会提示重新选择。网站与程序也可以在不同非 C 盘，无需放在一起。

## 添加照片到网站

1. 顶部选择网站根目录（包含 `index.html`、`js/data.js`、`css/style.css`），点击“读取网站内容”。
2. 选择多个文件或整个文件夹。程序会记住这个网站上次选的照片目录，方便下次继续选择。选整个文件夹后，“新照片上传到哪个文件夹”自动使用它：如果照片原来就在网站 `assets` 内，直接使用原目录；如果在网站外，则复制进 `assets/images/所选文件夹名`，保留子目录结构。上次使用的存放目录也会按网站分别记住，读取网站或重启后不会重置。
3. 在“新照片上传到哪个文件夹”中选存放位置，例如 `assets/images/bowu/qtq`。也可以直接填写新的子目录。这里先复制到本机网站里，上传到网上另点 GitHub。
4. 在“照片添加到哪个相册”中选择相册。已有相册会自动推测公共图片目录，检查是否正是你要的分类；例如“文物介绍及科普”跨多个目录，青铜器请手动选 `bowu/qtq`。输入新相册名字会自动创建；留空则只复制文件。要填星标、简介等资料，点击“新建 / 修改相册”。
5. 单批照片可以直接点击“添加全部照片并更新网站代码”。需要多批传到不同位置时，才用“加入待添加列表”，最后一次添加全部批次。

“预览文件 / 照片”可以查看选中的文件或待添加批次，左侧是文件列表，右侧显示选中图片；可切换原图与处理后效果，检查 PNG 底色、压缩尺寸和实际保存路径。双击待添加列表中的一批，可只预览这一批。添加完成后，这个按钮仍可查看刚保存到网站里的图片。

“获取本次照片 data.js 代码”第一个标签只显示本次新增照片对应的代码条目，不会把以前所有照片混进来；第二个 `data.js` 标签提供合并后的完整文件。可以复制或导出。代码里的文件扩展名与实际处理结果保持一致，例如 PNG 转 JPG 后生成 `.jpg` 路径。照片已经登记的路径会跳过；刚完成添加后仍可取到这次的代码。

程序保留导入源文件，复制并处理目标副本，自动追加相册照片、去除重复路径。同名文件默认直接覆盖，不保留覆盖前的副本；取消“同名文件自动覆盖”后，同名不同内容会停止。队列中两个文件产生同一目标路径时停止。

选择照片或文件夹后，页面中间的列表会立即按文件逐行显示文件名、格式、大小、保存位置、相册和状态，无需先点击加入列表。已有目标会显示“自动覆盖”，添加完成后保留“已添加”的文件信息。可选中单个或多个待添加文件移除；双击某一行查看该文件的图片预览。选择下一批文件时，显示新一批的明细。

“移除选中文件”右侧有“刷新列表”。在文件管理器里改名、修改或删除照片后点它：选择整个文件夹时会重新扫描，包含新文件；只选了部分文件时会更新这些文件，并识别同目录内的改名，不会把其他未选照片混进来。列表选中图片后右键“在文件管理器中显示”可打开并定位该文件；右键菜单也提供刷新。

照片列表和新增照片的代码按序号排列：如 `photo1、photo2、photo10`，以及 `景点 其一、其二、其十、十一、十二`。同一标题的一组照片按序号排序，新照片按此顺序追加到相册。

网站的个人简介、旅行随笔、平台入口、城市和联系方式集中在 `js/data.js`；该程序会自动管理照片集部分。其他文字仍可编辑 `data.js`，也可点击“预览网站”查看，原有 `add-tool.html` 继续可用。

## 新建或修改现有相册，获取代码

进入“相册与代码”：

- 新建：点“创建新相册…”，输入名称并确定，会立即创建并加入两个相册列表，自动跳到“添加照片”并选中它。之后选择照片和存放文件夹，点击添加即可。需要印章、星标、关键词、简介和封面时，可再到“相册与代码”选择它修改。也可在空表单填好资料后点“创建相册并加入列表”。网站预览会显示没有照片的空相册，并提示等待添加照片。
- 修改：从上方下拉框选现有相册，资料自动填入；可更名、增删关键词、更换封面、修改或清空简介、开启或取消星标。既有照片和其他未编辑字段保留。网站中指向这本相册的 `openAlbum` 快捷入口会按网站的全名或简称匹配规则随更名更新。
- 显示顺序：填写“相册显示顺序”第几个，或点“前移 / 后移”，再保存。`1` 表示网站第一本相册，程序会实际移动 `SITE_DATA.photos` 中该相册的位置，并更新程序里的相册列表。照片、其他相册、星标等内容保留。新建相册默认排在最后，也可在创建前指定位置。
- 关键词支持逗号、顿号、分号分隔，例如 `青铜器，镇馆之宝`。它们是网站里按照片标题筛选的分类，不会自动给照片增加关键词。
- 简介从网页实际使用的 `album-desc.js` 优先读取，保存时同时更新该文件和 `data.js` 的备用简介。可分段；不要使用 `#` 开头的标题行，它会被网站误识别为另一本相册。
- 点击创建或保存相册才会修改文件。网站代码在表单读取后被其他操作改过时，保存会停止；重新读取后再编辑。保存后直接生效，不提供撤销。
- “生成 / 获取 data.js 代码”可预览修改后的完整 `data.js`、完整 `album-desc.js` 和相册片段，并复制或分别导出。仅预览、复制不会改网站。导出完整文件时，简介文件也需对应使用；相册片段用于放入 `SITE_DATA.photos` 数组。
- “添加照片”页的代码按钮专门对应当前选择、待添加的照片；没有待添加照片时提供最近一次成功添加的代码。

## 预览本地修改

顶部、“添加照片”页和“相册与代码”页均有“预览本地网站”。先保存相册资料或完成照片添加，再点击按钮，浏览器会打开当前选中网站文件夹里的 `index.html`，可以检查照片、简介、关键词、封面和星标是否符合预期。后续保存新修改后，在浏览器按 `Ctrl+F5` 刷新。预览显示电脑里已保存的网站内容，不需要先上传 GitHub；确认满意后再上传到网上。

## 外部增删、改名后：检查图片与代码

在文件管理器中删除或改名照片，不会自动改变 `data.js`。在“添加照片”页点击“检查图片与代码”，按下面流程核对后再上传 GitHub：

1. **检查**：只读扫描当前网站，列出相册、封面中的失效图片路径、同相册重复登记、路径大小写不一致和未在 `data.js` 使用的图片。其他栏目如肖像、游记封面缺失时会提示手动处理；远程图片链接不做联网检查。
2. **选择删除**：在“删除照片代码”中自己选中要删除的行，再点“删除选中的照片代码”。可删除缺失照片的代码、失效封面引用或重复登记。只改你选中的代码，不删除图片文件；其他相册、简介、星标和照片保留。大小写或其他路径提示只供核对，不会自动调整。
3. **选择增加**：在“增加图片”中选择确实需要上网站的新照片，选择或输入相册名，再点“增加选中的图片到相册”。仅添加所选照片的代码，文件不移动、不重复压缩。图片可能属于页面装饰等其他素材，请自行确认用途。
4. **复查与预览**：删除或增加后自动复查。可以导出 CSV 报告，也可以手动“重新检查”，然后预览本地网站，确认后再上传 GitHub。

检查本身不修改代码，默认不选中图片。只有你选择删除或增加并点击按钮后才保存。保存前会核对代码和文件状态；有变化则要求重新检查。不保留修改前的副本，请核对选择后操作。同名替换图片内容通常不需要修改代码，刷新网页即可。

## 图片、PNG 和 ZIP

图片压缩的默认输出目录是顶部当前选中网站下的 `assets/images`。当前网站对应 `F:\WorkBuddy\personal-website\assets\images`；换电脑或切换网站后会自动使用新网站的对应目录，也可手动选择其他输出目录。

导入默认沿用原有脚本规则：转 JPG，最长边 1600、质量 82；不超过 800KB 且尺寸合适的 JPG 保持原样。PNG 真透明区域默认填网站卡片纸色 `#F6F0E2`；可改为页面纸色、自定义色或取色。“PNG 保留透明和格式”可避免转 JPG。白底不透明 PNG 不会去白底。GIF、SVG、动画图片保留原样。

源、输出目录不同时保留原图和子目录；**两个目录相同时原地压缩，只保留处理后的文件**，例如 PNG 转 JPG 成功后删除原 PNG。先生成处理结果再写回，不复制原图备份。开启“PNG 保留透明和格式”时仍保留 PNG；GIF、SVG、动画保持原样。

原地压缩网站 `assets` 内的图片时，会同步 `data.js` 的格式转换路径。先保存新文件和代码，再移除转换前文件。网站外压缩不改网站代码。不生成备份，不提供撤销。源、输出目录可相同或互相独立，不支持彼此包含的不同目录。

输出同名文件直接覆盖，不保留旧副本。同批转换重名时后处理的覆盖前面的。生成 ZIP 时也会替换同名压缩包，先完整写好再替换；ZIP 须在源目录之外。网站 ZIP 排除隐藏目录、`.git` 和桌面工具等工作文件。

## 批量重命名

选择文件夹、命名规则，点击“生成预览”，检查后执行。默认只处理这一层，可包含子文件夹；处理普通文件，也可按名称是否含中文筛选。

已经改好名字的文件再次预览仍会显示，状态为“名称不变”；真正需要修改的显示“将修改”。执行后自动重新读取预览，仅改名的文件会执行，名称不变的不会重复处理。

- “其一／其二”：直接复用现有 `rename_qi.py` 的分组规则。`天安门01.png`、`天安门05.png` 变为 `天安门 其一.png`、`天安门 其二.png`；十一开始不加“其”；单张去掉编号。
- “前缀＋数字”：例如前缀 `bj`、起始 1、补零 3，生成 `bj001.jpg`。

网站内文件改名会同步 `js/data.js` 中完整路径相同的字符串引用，保留原有注释与其他内容；自行写在其他文件中的图片路径需要自行更新。预览后更改规则需重新预览。对照 CSV 在对应历史目录内。

## GitHub

“一键上传 GitHub”会直接弹出你原有 `push.bat` 的可见命令行界面，显示 Git 的真实传输进度、错误和交互提示，更新说明、账号登录、仓库及冲突选项都在该窗口填写或选择。上传脚本已打包进程序资源，不需要另外携带 `push.bat`；本机仍需要安装 Git。

上传始终针对顶部当前选中的网站目录，和 EXE 存放位置无关。脚本被临时写到程序自己的非 C 盘 `_data/upload-sessions`，不会覆盖网站根目录原来的 `push.bat`。上传范围、25MB 检查、提交、合并和替换选项沿用原脚本；程序不会替你输入选项。打开窗口不代表上传成功，以脚本里的 Git 结果为准。

网络慢或无响应时可以在该窗口按 `Ctrl+C` 中止，关闭窗口后再点击上传重试。本地提交成功但上传失败时，提交仍保留。HTTP 上传连续约 60 秒几乎没有数据时启用 Git 的低速退出设置。上传窗口独立显示，主程序不会因为等待网络而失去响应。

## 自己设计图

“我的设计”可设置窗口图标和右上角横幅，直接选择自己的 PNG、JPG 或 ICO。素材会复制到程序旁的 `_data/design`。窗口图标建议 256×256 以上透明 PNG，横幅建议 720×180。

EXE 文件本身的图标在打包时固定：将设计命名为 `custom-icon.png` 放到源码 `desktop-tool` 目录，再运行 `build.ps1`。默认图标用网站纸色和朱砂绘制的山水几何图案，不需要额外图片服务。

## 缓存与磁盘

照片生成代码时，同名系列按数字及中文序号排列，例如“其一、其二、其十、十一、十二”。添加照片或生成相册代码时，也会整理这本相册已有的照片：同组归在一起，按各组首次出现的顺序展示。网页缩略图、搜索结果和大图浏览使用相同顺序，相册之间仍按自设顺序展示。

底部只保留“清除缓存”按钮。程序不再生成 `.bak` 和操作备份，没有撤销、备份目录、24 小时定时清理功能。配置、自定义图标与日志保存在程序旁 `_data` 中。

只临时保存处理所需的结果文件，结束（含出错）后立即清理。完成的输出直接保存，中途出错时保留已完成结果，可再次执行。

“清除缓存”清理临时文件、图片信息缓存及旧版本残留的 `history` 备份，不删除网站照片、原图、设置或图标。被占用的文件会跳过，上传窗口打开时请先关闭再清理。上传大小检查遵循 `.gitignore`，不再因被忽略的程序缓存而误拦截。

程序拒绝向 C 盘写工作文件。启动临时目录、打包缓存也均设为非 C 盘，不需要安装。Git 使用你已有的安装与认证配置。

## 源码与打包

源码需要 Python 3.8+、Pillow；打包还需要 PyInstaller。可直接运行“启动源码版.bat”。当前机器已有这些依赖。

在 PowerShell 中运行：

```powershell
.\build.ps1
# 指定 Python：
.\build.ps1 -Python 'G:\ProgramData\Anaconda3\python.exe'
```

产物在 `dist/ShanshuiManager/ShanshuiManager.exe`，依赖位于旁边的 `_internal`。采用文件夹便携版，避免单文件 EXE 启动时默认解压到 C 盘临时目录。
